# Phase 09 — Legacy Admin Route Authorization Inventory

Generated from route registrations in `src/routes/{adminAuth,adminAccess,adminDashboard,adminOrders,adminCatalog,adminOperations,adminSettings,phase06,phase08Admin}.js` and the `adminSettings.js` settings-page map. Exact method/path entries below are guarded by the global fail-closed middleware after session refresh; each route module also retains its existing `requireAdmin` where present. Unauthenticated requests continue to the module’s existing auth behavior. Effective permission checks are server-side; hidden links are not treated as authorization.

**Inventory:** 252 unique active method/path endpoints from 261 route registrations (9 duplicate method/path registrations, resolved by actual mount order); 139 state-changing endpoints; GET 113, POST 135, PUT 2, PATCH 2. 0 unmapped. The HTTP integration test sends each listed method/path as a logged-in zero-grant user and requires 403; a unit policy matrix tests allow/deny for each mapped entry. Representative full-stack allowed behavior is tested for dashboard, access lifecycle, polling, popup, assistant and audit. It does not claim successful business-operation coverage for every legacy handler.

## Enforcement and limits

- All authenticated `/admin` paths except the existing login/root flow resolve through `policyForAdminRoute`; unmapped routes fail closed even if a role has unrelated keys. Current inventory is the source for reviewing new registrations.
- Every authenticated non-safe `/admin` request requires the session-bound CSRF token. Admin templates add the token to legacy forms and same-origin `fetch`; existing per-route CSRF guards remain. `GET /admin/clear-cache` is now 405; the state change is POST + CSRF.
- Existing explicit Phase 06/08/09 and dashboard audit writers are retained. Other successful legacy mutations emit a minimal `admin.legacy.<permission>.mutation` event before the response is sent; event contains method/path/permission/status, not submitted body. Audit failure returns 503 and explicitly warns that the mutation may already have applied; old callback-based mutation handlers are not transactionally coupled to that generic audit insert.
- CSV report exports produce a minimized audit event. Ordinary reads are not all audited to avoid high-volume data collection.
- Admin operations on vendor/reseller records are platform-wide administrative operations, not vendor-tenant scoped. Vendor/reseller self-service route modules are outside the `/admin` inventory and retain their own portal authentication. No tenant-scoped admin data boundary is claimed.
- `BLOCKED`: role grants are owner-controlled and unassigned by migration. Non-Super-Admin operation requires approved grants. Business-level success tests are not exhaustive for every legacy route; the blanket HTTP deny sweep and per-route policy matrix are automated.
